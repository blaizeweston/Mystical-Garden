# Mob simulation

The replacement enemy framework and its native core. Only the Neural Arena runs it. Normal play keeps the legacy enemy code until a host setting adds this framework. The `.gdignore` file keeps the folder out of the editor scan and exported builds. See [docs/ENEMY_FRAMEWORK_PLAN.md](../docs/ENEMY_FRAMEWORK_PLAN.md) for the design and phases.

## Layout

| Path | Purpose |
|---|---|
| `native/mob_nav.c`, `mob_nav.h` | Engine-free core: clearance grid, flow fields, line of sight, crowd movement |
| `native/mob_nav_gdextension.c` | Godot binding for the `MobNavWorld` class |
| `native/mob_nav_test.c` | Core tests that run without Godot |
| `native/mob_exec.c` | Behaviour executors and the movement speed pass |
| `native/mob_decide.c` | Legal-action masks and the scripted brain |
| `native/mob_sense.c` | Perception, ally slots, light, hearing and smell |
| `*_reference.gd` | GDScript versions of the native systems, kept for the parity test |
| `mob_status.gd` | Damage over time, dodge windows, channeling and armour |
| `mob_release.gd` | A release's areas from its kit row, and the hit test for each |
| `native/build.ps1` | Builds and tests the core, then links `bin/mob_nav.dll` |
| `mob_nav_world.gd` | Loads the extension and bakes it from a configured `Battlefield` |
| `mob_sim.gd` and the other `mob_*.gd` files | The mob architecture layers described in the migration guide |
| `mob_contract.json` | Behaviours, action heads, slot counts and rule values |
| `definitions/` | Typed enemy definitions, the loader and the table compiler |
| `data/` | Ability, species and mutation data for every catalog species |
| `perf/` | Per-system timers and speed budgets |
| `tests/` | Contract tests, binding test, speed comparisons, map accuracy checks and multi-process throughput |

## Build and test

The build uses LLVM-MinGW 20251104 and the interface header generated by Godot 4.7.2. Override `-Toolchain` and `-Interface` if they are stored elsewhere.

```powershell
./mob_sim/native/build.ps1
godot --headless --path . --script res://mob_sim/tests/mob_nav_binding.gd
godot --headless --path . --script res://mob_sim/tests/mob_nav_verify.gd
godot --headless --path . --script res://mob_sim/tests/mob_nav_bench.gd
godot --headless --path . --script res://mob_sim/tests/mob_definition_checks.gd
godot --headless --path . --script res://mob_sim/tests/mob_sim_contracts.gd
godot --headless --path . --script res://mob_sim/tests/mob_native_parity.gd
godot --headless --path . --script res://mob_sim/tests/mob_sense_checks.gd
godot --headless --path . --script res://mob_sim/tests/mob_status_checks.gd
godot --headless --path . --script res://mob_sim/tests/mob_sim_bench.gd
./mob_sim/tests/run_bench.ps1
./mob_sim/tests/run_throughput.ps1 -Processes 12
./mob_sim/tests/run_throughput.ps1 -Processes 12 -Script res://mob_sim/tests/mob_sim_bench.gd
```

## Known differences from `Battlefield`

- Barrier corners are round for movement because clearance is a true distance. `Battlefield` grows barriers with square corners.
- Mobs keep their body clearance from the outer edge of authored arenas. `Battlefield` applies no clearance there.
- The clearance grid can read about 0.08 units high right at a sharp corner, so movement adds a 0.06 unit safety margin.
- Line of sight can disagree with `Battlefield` only when a line grazes a floor edge within 0.09 units.
