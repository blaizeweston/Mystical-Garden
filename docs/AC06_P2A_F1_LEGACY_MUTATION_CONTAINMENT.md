## Corrected writer inventory

| Legacy entry point | Mutation interval and evidence exclusion |
|---|---|
| `SaveBatch.write/write_bytes` | Canonical Garden/profile or known catalog/tombstone, plus reserved scratch. These public entry points refuse raw sidecar and arbitrary production paths. Guarded metadata/archive code uses the internal raw writer within its existing context. [Batch](../save_batch.gd#L10) · [Guarded metadata/archive](../persistence_operations.gd#L200) |
| `SaveBatch.begin/write/commit/cancel`, `GameTransaction.run` | The bare batch stages in memory and acquires the gate for the complete canonical set at commit. The gameplay wrapper holds it from before the callback through serializer backups, staging, legacy journal, replacement, and cleanup. A bare batch cannot run a serializer that could publish a backup outside the owning operation. Cancel clears in-memory staging. [Batch](../save_batch.gd#L51) · [Gameplay transaction](../game_transaction.gd#L24) |
| `Progress.save_garden`, `CharacterProfile.save_profile` | Standalone serializers exclude pending evidence before backup or scratch creation. Nested serializers use the exact path already in the gameplay or slot scope. [Garden](../progress.gd#L235) · [Profile](../character_profile.gd#L127) |
| `SaveSlots.prepare/ensure_character` | Legacy import scopes the sources and proposed destinations and repeats eligibility under the gate. Directory-only setup uses native bootstrap. Profile creation and reads in `ensure_character` are scoped to the selected slot. [Slots](../save_slots.gd#L21) |
| `SaveSlots.new_game/new_world/delete_save/delete_world/archive_deleted_save/restore_deleted_save` | A single interval covers vacancy and lease checks, archive creation, scratch or replacement, tombstone and cleanup. The slot scope includes Garden, its legacy profile and deletion metadata. Archive names and ancestry are checked before directory creation. Compensation is available only to the owning operation. Developer Garden creation/reset follows these same routes. [Slots](../save_slots.gd#L93) · [Archive/compensation](../save_slots.gd#L222) · [Developer Garden](../developer_mode.gd#L30) |
| `CharacterSlots.prepare/create/update/delete_character/remove_character/set_capacity/remember` | The operation checks the selected profile and shared roster catalog. Import revalidates eligibility and destination before writing. Edit and delete keep the lease, serializer, archive and catalog changes under the gate. Roster summaries no longer invoke recovery. [Roster](../character_slots.gd#L21) |
| `SaveSlots.claim/heartbeat/release/remember_slot`, title launch | Lease and selection writes check evidence for their selected save. Legacy title launch preflights and holds a single gate over the profile/Garden lease claims. Join checks only the roster profile and does not claim a Garden. Existing heartbeat expiry stays at 30 seconds. [Leases and preference](../save_slots.gd#L141) · [Title launch](../main_menu.gd#L611) |
| `SaveBatch.recover`, recovery-capable legacy loads | Only a validated, untagged legacy journal may use this executor. Discovery includes reverse membership, absent participants and anchors. The plan and observations are checked again under the native lock. A guarded marker, durable artifact, malformed link, contradictory scope or unproven ownership refuses. B2 remains the recovery path for guarded evidence. [Legacy recovery](../save_batch.gd#L62) · [Discovery](../persistence_recovery_plan.gd#L24) |

The existing Windows native root handle spans discovery and mutation. Nested legacy calls must stay within the owning scope. A legacy writer called from an already-held guarded operation without its own authorized route is refused. Bounded discovery can conservatively block other saves when evidence ownership cannot be resolved. Missing directories are rechecked under the lock before a scoped writer creates them. Scoped refusal snapshots include metadata, lease markers, archives, scratch, and all canonical files. They exclude the lock sentinel and diagnostic output. ## Remaining limitations

The lock coordinates processes that use this build's boundary. Older executables and external filesystem changes are outside that protection. Legacy slot copy/replacement retains its prior sequential format and is subject to interruption between files. A malformed or unresolvable journal, link, or reserved scratch can require operator review. No ambiguous artifact was removed by the correction. Canonical production paths require the compatible native backend on supported Windows storage. The existing fixture-only save namespaces are limited to isolated headless validation. The release smoke uses its own disposable paths.

The separate identity-less import and recovery-selection findings from P2A remain open. Production cutover remains a separate approval. No live saves or installed binaries were modified.
