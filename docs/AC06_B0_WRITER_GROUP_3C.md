## Lifecycle and auxiliary changes

- Guarded hosting requires ownership of the selected Garden. Host registration saves the Garden-side growth receipt before marking a peer ready. Verified failure, unresolved recovery, and cleanup-pending block admission. A rejected peer timer is bound to its original transport. The guest revalidates its selected profile or commits the incoming projection through its own lease before declaring Join complete. The host still lacks a durable guest acknowledgment.
- Window close, leave and title return use the same guarded exit preflight. An owned expedition settles once. An initial verified abort or uncertainty keeps the current world visible. A later exit from a blocked world only detaches and returns to passive browsing. Cleanup-pending returns to title with the committed bytes and a separate retained warning. The return scene skips automatic legacy import preparation.
- A terminal session may relinquish its own exact `session.cfg` digest under the native root lock, even if a canonical journal is pending. PID and digest must match and the marker scratch must be absent. This route cannot acquire or renew ownership, inspect or repair the journal, or write a save. A contention or validation failure leaves the marker to ordinary expiry and is recorded. AC-02 ordering remains in the explicit exit paths.
- The real title co-op fixture reproduced the open focus-loss defect. During title construction the departing guest could send `submit_combat` to itself after the offline peer replaced ENet. The release handler now checks for the live host transport. Peer-disconnected on a departing client no longer enters host loot cleanup. Neither fix changes combat input or the wire protocol.
- Application and network settings keep their existing ConfigFile sections. `PreferenceFile.write` uses a unique sibling scratch and a standalone replace, returning its own IO error. Neither call stages a participant or mutates the first serializer error. Failed AppSettings writes leave applied preferences unchanged. Network preference failure remains separate from Join and is diagnosed. This settings path has no B1/B2 recovery or cross-process read/modify/write guarantee. The Garden selection preference under the save root is a different file and stays in slot management.
- Diagnostic breadcrumbs inside transactions are attempt observations. Their return values never decide commitment. Legacy gameplay metrics buffer under the legacy batch and flush after its result. Guarded upgrade, encounter-clear and Wilds-learning metrics already queue post-commit effects. Floor generation metrics are presentation observations. A metrics IO failure neither latches nor rolls back a canonical transaction.

## Cutover decision

**Blocked.** The production flag remains false and `VERIFIED_WRITERS` remains empty. The activation inventory now identifies default legacy entry points separately from the auxiliary writers. These conditions remain before approval:

1. Route every default title, Developer Garden, world, roster, serializer, lease, and shutdown writer through verified guarded production paths. Preserve recovery and destructive refusal across all supported Garden, legacy, roster, and Preview roots.
2. Provide an explicit recovery workflow for pending evidence. Continue to refuse ambiguous or unverifiable records, legacy committed journals without independent proof, and ambiguous archives. Test every migration and backup failure phase and re-check prior saves without modifying originals.
3. Finish Stage A serializer-first-error and migration-state coverage on production callers, and the guest acknowledgment boundary. A host commit does not certify a guest profile save. Older projections still do not support arbitrary historical replay or durable acknowledgment of non-monotonic changes.
4. Establish older-build exclusion or separate roots before any production cutover. Old binaries ignore the native sentinel and B2 evidence. A network protocol check cannot protect a shared local save root. Keep an independently verified pre-cutover backup and prohibit old builds from opening a migrated live root.
5. Run final production-path source, Windows package, interruption and multiplayer release acceptance with the matching x64 native DLL. Current evidence is local NTFS and localhost. It does not establish sudden power-loss durability or WAN behavior.
