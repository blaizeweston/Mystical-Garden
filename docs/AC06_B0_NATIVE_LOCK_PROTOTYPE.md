**Result:** Feasible on the tested Windows x86-64, local NTFS setup. ## Prototype and build

The GDExtension exposes `acquire(absolute_path)`, `release()`, `is_held()`, and `last_error()`. It keeps the live native handle in the instance. Acquisition calls `CreateFileW` with `GENERIC_READ | GENERIC_WRITE`, zero sharing, `OPEN_ALWAYS`, and null security attributes for a non-inheritable handle. Failure leaves a fresh instance without a handle. The sentinel stays on disk after release. The probe performs its protected write only when acquisition returns zero and the instance reports a held handle. The build uses portable LLVM-MinGW `20251104` (Clang 21.1.5, UCRT, x86-64), the C ABI header generated by Godot 4.7.2 revision `ed1daf0bf`, and the installed Windows x86-64 release template. The portable compiler archive was verified against SHA-256 `171b298f46fa4b5653dc7b01cc5e709caca645991be8e1b0724466c4a282a1ac`. The build needs no Visual Studio, SCons, CMake, godot-cpp, or custom engine. The successful DLL imports `KERNEL32.dll` and Windows UCRT API sets. Python 3 runs the verification harness. An earlier Zig 0.15.2 attempt encountered cache/output access errors in this environment. LLVM-MinGW completed the build. ## Remaining limits

- The sandbox denied junction and hard-link creation. Those alias types were unverified. The wrapper accepts drive-absolute paths and relies on Win32 to resolve the aliases it receives. The production caller would still need to select one canonical sentinel under the user-data root.
- The raw C wrapper pins the tested Godot revision. Other engine revisions, CPU architectures, and redirected or network filesystems were unverified. The prototype used the editor executable headlessly and the release export template.
- A production release would need to install and verify both files together. The current release script copies only the EXE. Save writer integration and journal recovery remain separate work.
