# AC-06 P2A-F3 — Candidate production release acceptance

## Decision

**P2A-05's startup bypass is corrected in the automated candidate harness. Production cutover remains NO-GO.** Both source and Windows package fixtures used the configured main scene, the candidate title route, real title handlers and the normal world handoff. Recovery cases ran through the title and Developer Settings controls. `PRODUCTION_CUTOVER_APPROVED` stays false and `VERIFIED_WRITERS` stays empty.

The starting checkout was clean on `ac06/persistence` at F2 `245dc9c2e1746642eb8af8419561dbb1f7f95362`, directly above F1 `74e0235468e76a0d5df7737fd6beeb28d07f48b6`. All 1,266 F2 tested inputs matched the Git blobs after text line-ending normalization. The F2 verifier rechecked 44 normal verdicts with 60 process exits, four original defect reproductions, 64 case records and the interruption evidence. The current checkpoint also reran the corrected F1/F2 fixtures and F2 interruption cases.

## What the release harness now does

- The solo fixture opens New from the title, confirms the real character creator, verifies both lease owners, tests harvest, inventory, combat reward settlement, departure, checkpoint, extraction, Continue, return and window-close notification. Direct world construction appears only in refusal cases with missing or stale ownership.
- The party fixture starts every process from the configured title. It uses Host and Join with real loopback peers, admits four players, refuses an overflow peer, exercises guarded harvest and a guest profile commit acknowledgment, reconnects through the title, refuses a delayed profile write after local lease loss, and verifies shutdown and owned lease release. The version 39 case uses a real RPC sent by the current fixture. Version 40 admission checks the guarded capability. Historical executable interoperability remains deployment evidence to collect.
- The Windows release helper treats catalog/exclusion, candidate title acceptance and the supplied four-player smoke as independent gates. The planner always schedules all 12 candidate-tagged package suites fresh. Package commit rejects omission, reuse, a mismatched companion DLL, stale result IDs, unexpected engine errors and failed peer exits. Source release verification requires current evidence for every registered suite.
- The candidate opt-in requires a headless editor/debug host, SceneTree metadata, a validation run marker and a disposable root under `.godot/vd`. The external fixtures are excluded from retail export. A standalone release-template executable started normally under the test environment marker with cutover disabled. The standalone release executable also ignored an externally supplied test driver. The candidate path refuses missing, wrong or stale lease ownership before world initialization.
