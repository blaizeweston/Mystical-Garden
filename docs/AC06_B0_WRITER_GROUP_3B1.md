## Authorization and finalization

GameTransaction.run_gameplay dispatches scoped actions and exposes their business value after run_guarded confirms commitment. PersistenceOperations.run_management discovers the required participants, journals, leases, tombstone scratch and serializer migration paths, then revalidates under the native root lock. The gameplay transaction checks ownership before acquiring the lock, inside it, and before staging the final state. Nested operations can reuse already-bound serializer objects and paths. Only the outer owner finalizes. World-owned serializers refuse unbound legacy writes and recovery-capable reads. Passive reads remain available.

| Result | Gameplay and disk handling |
|---|---|
| COMMITTED | Keep state and return the business value, including false or null. |
| ABORTED_RESTORED | Restore the Garden, Heart, campaign, players, profiles and RNG snapshot if the action ran. Original bytes or recorded absence were verified. |
| COMMITTED_CLEANUP_PENDING | Keep committed state and block further writes in the affected world pending cleanup. |
| UNCERTAIN | Keep tentative memory and recovery evidence. Withhold success and block replay. |
| Authorization or lease refusal | Skip the gameplay callback and preserve the originals. |
| Pending or ambiguous evidence | Refuse the callback, preserve evidence and block further gameplay writes. |

SaveBatch retains the first participating serializer failure. Helpers that used standalone saves and local rollback allow the guarded owner to serialize and decide rollback. Their legacy branches retain the immediate saves. The guest receiver still uses the existing RPC. This checkpoint does not add multiplayer success publication.
