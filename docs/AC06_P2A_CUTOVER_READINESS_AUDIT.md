1. **P2A-01 — Reverse-only guarded scope can be overwritten in legacy mode.** On both builds, a real committed cleanup-pending G+P batch was created and the P forward link was absent. The B2 planner still resolved both participants, but legacy `SaveBatch.write(P)` returned OK. P changed and the expected evidence stayed intact. The planner then returned `committed_state_mismatch`. The evidence is preserved in the disposable root. Before a shared-root deployment, prevent the legacy route from writing against all participants in guarded evidence, including reverse-only membership. ## Older-build exclusion policy

| Option | Safety and rollback |
|---|---|
| Explicit physical root separation | Strongest exclusion for a controlled rollout when old executables resolve only their old physical root. Keep the old root frozen for rollback and make the new root distinct, with no junction, symlink or settings override linking them. |
| Versioned directory under the existing root | Sufficient only if every old writer, recovery scanner, discovery and launch mode provably ignores the new subtree. A sibling physical root also separates global scans and lock sentinel identity. |
| Verified one-time migration | Complement to isolation. Copy from a quiescent backup, confirm origins, identities, versions, tombstones and journals, preserve bytes and emit a manifest. Refuse uncertain evidence. Publish the completed destination only after validation. Repeated runs must deduplicate and refuse collisions. |
| Existing-root activation with operational exclusion | Weakest. Replacing or renaming the installed EXE cannot prove another older copy will never open the root. Requires administrative exclusion of all old copies and tested concurrent launch refusal. |

**Recommended minimum** is a distinct physical save root plus an explicit, restartable copy migration from a verified backup. Require approval before creating the root or migrating live data. Test an old executable and candidate side by side against disposable pre-cutover data, including legacy root, roster, Developer and Preview paths. Prove that the old executable changes only its old root, that aliases cannot point either writer into the other's root, and that a terminated migration either resumes safely or refuses with evidence. Test unsupported, redirected and unavailable roots. Retain the pre-cutover EXE/DLL and save snapshot together. Rollback opens only the old root and does not import newer guarded saves or replay acknowledgment history. Users will choose whether to import their older saves and all co-op participants will need a matching protocol and save mode. Post-cutover progress remains in the new root if they roll back.
