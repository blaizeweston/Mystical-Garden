Explicit-scale math in `combat_vitals.gd` still supports bounded data/unit conversion. Current damage, mitigation, healing, attack timing and enemy composition retain their former modern values. Seed/material descriptions now use explicit affinity identities rather than claiming old raw-tag passive bonuses.

Known modern enemy-learning gaps remain deliberately unexpanded: `AREA_PRESSURE` had a species-selected Ember Wake producer, but modern Fire has no authored production observation hook; shelter-break observations likewise came from the retired Core displacement path. Adding those producers requires an explicit AI/gameplay decision, rather than broadening native stagger or restoring Hush.

Historical **persistence** names such as `SaveBatch.Legacy`, `take_legacy_notices`, and contained serializer routes are not selectable old combat. They still protect live save transactions and issued guest-profile digests. Production AC-06 remains disabled. Uncommitted permanent rewards are held in host memory; a host process failure can lose work not yet settled. This cutover adds no durable journal and does not claim production persistence closure.

## Current restructuring plan

The 2026-11-18 source/research review changes the priority from additional small field extractions to complete behavior boundaries. Game is the world-scene composition and integration root: it wires dependencies, routes authorized requests, coordinates start/transition/exit and advances ordered simulation/publication stages. UI construction, class execution, outgoing-hit rules and snapshot assembly should have explicit owners. Line count is a symptom; editing clarity, actual dependency reduction and measured frame work are the acceptance criteria.

| Step | Boundary and acceptance | Status |
|---|---|---|
| 1a | Gameplay UI shell, HUD presentation, overlay lifecycle, checkpoint cards, travel and confirmation controls. One scene/controller owns controls and presentation state. It accepts focused detached display data and emits explicit local requests; it never receives Game or mutable actors. Remove replaced Game fields/builders and invisible superseded HUD work. Keep RPC entry points and domain transactions in their current owners. | Implemented and verified as the bounded first slice below. |
| 1b | Finish world-facing feature-panel ports. Replace the remaining broad feature-panel Game dependencies with focused read/command contracts as complete features; do not disguise them inside the shell owner. Move appropriate static layouts into editable scenes as those boundaries stabilize. | Inventory, gate-loadout, Tab, progression/research/story, Garden Altar, expedition graft and planting feature ports are complete. The growth cinematic port is also complete. Observation, crop/care, station, return, conduit and ambience views are now detached below. Existing domain services remain Game-bound; suitable editable static scenes remain pending. |
| 2 | Player combat execution: coherent native class-action admission/execution and outgoing-hit resolution using existing class/affinity/graft handlers. Establish shared resolved ability/build facts for combat, previews and descriptions, with explicit class/loadout/card/graft invalidation. | Shared Q/R execution, outgoing contacts/native hit batches, ordinary weapon launch/projectile lifecycle, and shared resolved combat values/tooltips are complete below. Casts and aim previews share range math. Specialist source/status ports remain coupled. Host publication and guest receive/reconciliation are complete below; remaining world presentation is separate. |
| 3 | Replication and remaining world integration: snapshot/detail builders consume owner projections; transport/RPC NodePaths, protocol 41, cadence/freshness and payload budget remain protected. Garden/session commands retain domain authorization and atomic settlement. | Host publication cadence, sequence/recovery ownership and detached public/owner projections are complete below. Guest receive/reconciliation ownership is complete below. Host reliable-health publication, base world guidance and the ordered effects/audio/map/Garden presentation pipeline are complete below. Avatar, spectator and dropped-item views now use detached facts below. Garden domain adapters remain coupled. Production AC-06 deployment is separate. |

For performance, first remove confirmed redundant work and then measure the same representative workload before/after. Do not assume moving code or adding more Nodes makes execution faster. UI-only changes should gain narrower test/change impact where the interface really permits it, without weakening shared-contract coverage. Preserve current implementations until their replacement works, then retire the replaced paths instead of keeping a selectable fallback.

The reference guidance is Godot's [scene organization](https://docs.godotengine.org/en/stable/tutorials/best_practices/scene_organization.html), [autoloads versus regular nodes](https://docs.godotengine.org/en/stable/tutorials/best_practices/autoloads_versus_regular_nodes.html), [lightweight objects](https://docs.godotengine.org/en/stable/tutorials/best_practices/node_alternatives.html) and [CPU measurement](https://docs.godotengine.org/en/stable/tutorials/performance/cpu_optimization.html). These are design principles, not a prescribed maximum size for game.gd or a reason to replace readable text content definitions.
