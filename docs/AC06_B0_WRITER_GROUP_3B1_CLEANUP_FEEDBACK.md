## Outcome and feedback contract

The original gameplay adapter returned the action value for both committed outcomes. Ordinary success paths treated that value as permission to close UI, show a success message or emit a cue. Those paths could overwrite the cleanup notice. The adapter now returns the existing persistence boundary and typed finalization alongside the business value, a notice, and an explicit completion flag. The canonical `committed()` predicate still includes both committed outcomes. [Gameplay adapter](<C:/Users/sutte/Desktop/The Garden Game development/Mystical Garden/game_transaction.gd:82>)

| Outcome | State and feedback |
|---|---|
| COMMITTED | Keep the committed state and exact business value, including false or null. Ordinary feedback requires completion and the caller's usual business checks. A separate authorization-release failure keeps the committed state and blocks ordinary completion. |
| COMMITTED_CLEANUP_PENDING | Keep verified canonical bytes, in-memory state and recovery artifacts. Retain the business value for canonical bookkeeping. Withhold ordinary feedback, show “Saved. Recovery cleanup is pending.” and refuse further writes. |
| ABORTED_RESTORED | Restore the snapshot and report verified rollback. A blocked cleanup after rollback keeps its own persistent notice. |
| UNCERTAIN | Keep tentative memory and evidence, withhold the gameplay value and ordinary success, and refuse replay. |
| Authorization refusal or pending recovery | Leave the callback unexecuted. A later refusal preserves the original pinned recovery notice. |

The HUD gives persistent save notices priority over local status assignments and received notifications. The notice survives toast expiry, remains visible over an open planting picker, and transfers to the title on guarded shutdown. The existing notification RPC carries the pending notice to the affected caller where applicable. No new RPC or automatic replay was added.
