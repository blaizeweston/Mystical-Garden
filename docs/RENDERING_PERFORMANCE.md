# Rendering performance and player visual preferences

## Reproducing the measurements

Use an imported editor/debug project and the Godot console executable. From the project directory run `python tools/render_benchmark.py --engine <executable> --cases probe,garden,combat,world --seconds 6`. The launcher creates a fresh marked profile and writes its location, engine log and JSON results. The driver refuses real storage and headless rendering. Select individual encounters with `--cases water,storm,spirit`, select `--size 1920x1080` or `2560x1440`, and use `--capture` for an explicit 8 Hz framebuffer readback, resize and JPEG write. `--cases isolate` measures CPU preparation and synchronized drawing separately. No driver cache is cleared.

All local results use the game camera, Godot 4.7.2 Compatibility/OpenGL, a GeForce RTX 5080 and Ryzen 7 9800X3D. The primary matrix uses 1100 × 720, VSync disabled. Each setup runs first at 120 FPS, repeats at 120, then runs uncapped. The process starts in the Developer Garden. “First” in the matrix means first use of that workload in that process. A separate launch is needed for a fresh process. Warm samples continue the same encounter. Each legal build uses three clustered targets, timed input requests and the existing practice lifecycle. Combat timing and target decisions can vary. The Grove, Mire and Hollow use depths 2, 10 and 16 and seeds 136, 137 and 129. The Grove is revisited in the same process.

Frame intervals include scheduling, simulation, interface, rendering and presentation waits. A frame above 50 ms is worth investigating even with a good p95. Each record includes sample size, median, p95, p99, p99.9 at 1,000+ frames, max and counts above 16.7/33.3/50/100 ms. Draws and primitives are the last periodic sample, effect counts are sampled peaks, and the engine's process monitor can still contain the preceding transition. Resource deltas are net counts. Neither a flat resource count nor a zero pipeline-counter delta proves that no allocations or driver work occurred. Timed scenario transitions include constructing the world and presenting it. The separately timed forced draw explicitly waits for the renderer.

## A. Diagnosis at VFX07B

The pre-optimization 1100 × 720 matrix exercised the starting Garden, developed Garden, 30 and 60 beds, ordinary strikes, Ember Wake, Avalanche ruptures, Monsoon, Conductor, combined Mirrorstep/Wraithcast, overlapping Void fields and a mixed build. The terrain trials used bridges where available, explored sight and real combat. The original layout hashes, observed effects and complete sample distributions accompany this report.

* At 30 beds the first six seconds after the fixture constructed the orchard had 11 frames above 50 ms, maximum 82.52 ms. The next capped pass had none and p99 was 8.70 ms. The initial developed Garden had one 72.24 ms frame. Bulk setup and steady Garden play must be reviewed separately. At 60 beds the warm uncapped p99 was 4.61 ms.
* Of the eight arena trials the first capped maxima ranged from 21.90 to 42.94 ms. The warm uncapped p99 ranged from 5.83 to 8.41 ms. This matrix did not reproduce a recurring active-combat frame above 50 ms. It does not explain the historical stalls.
* Generating a floor took 101–426 ms on the CPU. The first explicit Grove draw and sync took 24.49 ms and the repeat took 1.71 ms. A new floor view rebuilt identical family vegetation meshes in 5.78–7.77 ms. An immediate second lookup in that view reused the mesh. Re-entering the Grove rebuilt it in 6.93 ms. This identifies redundant CPU work on floor transitions.
* Previous measurements remain relevant. VFX03 had individual Garden frames around 31 ms. VFX05A had 46.92 ms with three burning targets. Monsoon reached 263.17 ms and fresh follow-ups roughly 33 ms. An uncaptured first-use Storm frame reached 310.41 ms and its repeat 10.24 ms. A Spirit recording frame reached 495.22 ms with framebuffer readback. Earlier forced first terrain draws reached 166.12 ms on VFX06B and 198.15 or 600.46 ms on VFX07, versus roughly 1.5–1.8 ms on repeats. The renderer, CPU, OS and capture contributions to these isolated frames remain unattributed. See [combat observations](COMBAT_READABILITY.md), [terrain draws](TERRAIN_GENERATION.md) and [Garden measurements](ARCHITECTURE.md).
* Isolating the 318 × 285 feature-distance texture took 41.21 ms for Grove, 75.91 ms for Mire and 15.74 ms for Hollow. Component measurements and texture byte digests allow a candidate to be checked for identical pixels independently of total floor time.
* A first Spirit release apparition took 4.26 ms to construct, 2.38 ms to seek through nine animation frames, and 154.05 ms in an explicitly synchronized full-scene draw. Nine repeats took 1.46–1.95 ms to construct and 1.39–2.05 ms to draw. An explicit repeat of all five numerical grip calibrations cost 0.33–0.51 ms per body. The sample supports reuse of immutable setup data, but does not attribute a historical 495 ms recording frame to skeleton setup or prove shader compilation. A separate warmed viewport sample reported 0.82 ms rendering CPU and 0.72 ms GPU. These timings cannot apportion the earlier full-scene wait.
* Two fresh, otherwise matched 1100 × 720 Spirit processes reached 54.77 ms without capture and 55.26 ms with capture on the first capped pass. Warm uncapped p99 increased from 6.68 to 11.61 ms with capture. The 1920 × 1080 Spirit pass and the higher-resolution standalone pass had warm uncapped p99 of 8.40 and 6.35 ms respectively. Windows constrained the requested 2560 × 1440 window to a measured 2560 × 1415. The 1080p workload followed Monsoon and Conductor, so its first Spirit sample has a different rendering history.
